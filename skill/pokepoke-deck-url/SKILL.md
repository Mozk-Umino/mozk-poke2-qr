# ポケポケ デッキURL

ユーザーと会話でデッキを決め、最後に **デッキURL** を出す。
ユーザーがURLを開くと、ゲームの「コードを読み取る」で読み込めるQRコードとデッキ一覧が表示される。
同じURLはブログやSNSでそのまま共有できる。

## 流れ

1. **相談**: 軸のポケモン、エネルギー、環境、手持ちの制約などを聞きながら案を出す
2. **確定**: 20枚の案がまとまったら、セット番号を確認する（後述）
3. **出力**: 下の「出力の型」でデッキ一覧とデッキURLを出す
4. **修正**: ユーザーから「違うカードが出た」「この番号はない」などと言われたら直して、URLを出し直す

途中の案ではURLを出さなくてよい。20枚が決まった時点、またはユーザーに頼まれた時点で出す。

## デッキのルール（これを外れるとQRが出ない）

- ちょうど **20枚**
- **同名カードは2枚まで**（イラスト違い・効果違いの同名カードも合算）
- エネルギーは **1〜3種類**: 草 炎 水 雷 超 闘 悪 鋼
- ドラゴン・無色エネルギーは指定しない（ゲーム内で選べない）
- 化石などトレーナーズ扱いのカードも、セット番号で書けばページ側で自動判定される

## デッキURLの形式

```
https://mozk-umino.github.io/mozk-poke2-qr/?n=<デッキ名>&e=<エネルギー>&d=<カード>
```

| パラメータ | 中身 | 例 |
|---|---|---|
| `n` | デッキ名（省略可） | `n=ミライドンex` |
| `e` | エネルギーを漢字1文字で続けて書く | `e=雷`、`e=雷超` |
| `d` | カードを `.` でつなぐ。1枚は `セット-番号`、2枚は末尾に `x2` | `d=B1a-24x2.A1-98x2.PROMO-A-7x2` |

- セットコードは `A1` `A2b` `B1a` `PROMO-A` など（一覧は `references/sets.md`）
- 番号は収録番号（カード左下の番号）。**番号でどのカード（版）になるかが決まる**（次の節）
- 同じワザ・効果のイラスト違い（レア版）はどの番号でも同じカードとして読み込まれる。**通常版（一番小さいレアリティ）の番号**で書く
- ポケモンとトレーナーズは分けなくてよい。並び順は「ポケモン → トレーナーズ」にすると読みやすい
- デッキ名に空白・`&`・`#`・`?`・`+`・`%` を入れない（空白が必要なら `%20`）。日本語はそのままでよい

完成例（20枚）:

```
https://mozk-umino.github.io/mozk-poke2-qr/?n=ミライドンex&e=雷&d=B1a-24x2.A1-98x2.B1a-26.B3a-19x2.A3a-21x2.PROMO-A-7x2.B3a-73.B1-225.A2-150.B1-226.B1a-68.A1-225.PROMO-A-5x2.A2-147
```

## カードの版（番号）の選び方 ― いちばん大事

**同じ名前でも、弾によってワザ・HP・効果が違うカードがある**（例: クイタランは A1-48・A4-37・B1-44・B4-29 がすべて別のカード）。
名前だけで選んだり、それらしい番号を書いたりしない。

1. **候補をすべて調べる**: そのカード名の番号を全部洗い出す（`lookup.py カード名` で同名の別カードが全部出る）
2. **中身を確かめてから選ぶ**: 候補ごとのワザ名・ダメージ・効果（特性・トレーナーズの効果）を攻略サイトやカード一覧サイトで確認し、デッキの狙いに合う版を選ぶ。カードDBにはワザ・効果が入っていない
3. **ユーザーの指定を優先する**: ワザの内容や弾の名前で指定されたら（「ベロのムチのクイタラン」「最新弾のクイタラン」）、それに合う番号を選ぶ
4. **確認できないとき**: 推測で決めず「確認できていない」と伝え、候補の番号とそれぞれの違い（分かる範囲で）を見せてユーザーに選んでもらう
5. **日本語名**: ユーザーが使った名前を優先し、次に攻略サイトの表記を使う。英語名を機械的に訳さない

## セット番号の確認

番号を記憶だけで書くと間違えやすい。次の順で確認する。

1. **コード実行が使えるなら** `lookup.py` を使う（日本語名・英語名・セット番号で検索、`--check` でデッキ全体を検証）。
   まず最新版をリポジトリから取って使い、取れなければ同梱の `scripts/lookup.py` を使う
   ```
   curl -fsSL https://raw.githubusercontent.com/Mozk-Umino/mozk-poke2-qr/main/skill/pokepoke-deck-url/scripts/lookup.py -o /tmp/lookup.py || cp scripts/lookup.py /tmp/lookup.py
   python3 /tmp/lookup.py ピカチュウ 博士の研究 "Giant Cape"
   python3 /tmp/lookup.py --check "B1a-24x2.A1-98x2...."
   ```
   日本語名はページと同じ変換ルールで出る。「日本語名未登録」はページでも英語名、「日本語名は推測」はページで「推測」と表示される
2. **Web取得だけ使えるなら** セットごとのJSONを見る（`set`・`number`・`name`(英語) が並んでいる）
   `https://raw.githubusercontent.com/flibustier/pokemon-tcg-pocket-database/main/dist/cards/<セットコード>.min.json`
   トレーナーズの日本語名は `https://raw.githubusercontent.com/Mozk-Umino/mozk-poke2-qr/main/data/names-ja.json`
3. **どちらも使えないなら** 記憶で書き、出力に「番号は未確認。ページのカード名が想定と違えば教えてください」と添える

カードDBの元データは英語名。ユーザーへの出力は日本語名で書き、日本語名が未登録・推測・不確かなカードは英語名も併記する（例: `ゲームコーナー（Arcade）`）。
DBに見つからない新カードは、DBの更新待ちの可能性があるとユーザーに伝える。

## 出力の型

~~~
## デッキ名（エネルギー: 雷）

**ポケモン（9枚）**
- コイル ×2（B1a-24）
- クイタラン ×1（B1-44 ベロのムチ）
- …

**トレーナーズ（11枚）**
- 博士の研究 ×2（PROMO-A-7）
- …

▶ [QRコードを開く](デッキURL)

（URLのコピー用）
```
デッキURL
```
~~~

- 採用理由や回し方は、一覧の前後に短く書く（ユーザーが求めた分だけ）
- **各カードに番号と版の目印（ワザ名や効果）を添える**（例: `クイタラン ×1（B1-44 ベロのムチ）`）。同名の別カードがないカードは目印を省いてよい
- 一覧の枚数合計が20になっていること、URLの `d` と一覧が一致していること、各番号の版が意図どおりかを出力前に必ず見直す
- 最後に「ゲームで読み込んだカードの版（ワザや効果）が意図と違っていたら教えてください。番号を直します」と添える

## ページでできること（ユーザーに案内する用）

- **QR画像を保存** → ゲームの「コードを読み取る」で画像から読み取る（スマホだけで完結）
- PCで開いた場合は、画面のQRをスマホのカメラで読む
- **まとめ画像を保存**（デッキ名・一覧・QRを1枚にした画像）、**Markdown / HTML をコピー**（ブログ用）。カード名は日本語で出る
- カード検索は日本語名（ひらがなでも可）・英語名・セット番号で使える
- ページ下の「デッキを作る・直す」で、カードの追加・削除やエネルギー変更ができ、URLも更新される
- ゲームのQRの中身（Base64）を貼れば、そのデッキのURLにもできる
